# How semantic-layer and AI-answer tools explain metrics, definitions and AI answers to business users (as of Nov 2026)

Scope note: almost every source is vendor documentation or a vendor blog, so it is biased toward each vendor's own framing. Docs describe what ships; they rarely show exact pixel layouts, so "visual" descriptions below are reconstructed from documented labels and sections. Where a label is quoted, it comes from the cited doc. Where I describe a layout beyond the documented labels, it is marked as inference.

## 1. Answer explanation: "how did the AI get this?"

### Takeaway
The products that have shipped agree on one pattern: the answer (a sentence plus a chart or table) sits on top, and below it are collapsible, plain-language explanation sections, with SQL hidden one click deeper. Looker labels it "How was this calculated?", Power BI "How Copilot arrived at this", and Genie "Analysis" (with "Understanding the question", "Found relevant data", "Referenced SQL example" and "Thinking steps"). In all three the user sees applied filters and can edit them. Raw code always sits behind a secondary "Show code" or Code tab.

### Cited Findings
- **Databricks Genie response anatomy.** An expandable **"Analysis"** section holds four subsections: "Understanding the question", "Found relevant data", "Referenced SQL example" and "Thinking steps", some shown only when applicable. Below that come a natural-language summary of the results, a result table with **"Show code"** to view the SQL, an optional visualization, and an editable **"Applied filters"** area. — [Databricks: Talk to Genie](https://docs.databricks.com/aws/en/genie/talk-to-genie)
- **Genie feedback row** has three actions. "Yes" means the answer looks accurate. "Fix it" opens a list of common issues plus a text field, with "Submit and try again" or "Submit". "Request review" flags the answer to the author, with an optional comment. Genie may ask a clarifying question before answering, and it suggests follow-up questions below each response. — [Databricks: Talk to Genie](https://docs.databricks.com/aws/en/genie/talk-to-genie)
- **Looker Conversational Analytics, "How was this calculated?"** This opens a **Text** section with "a plain text explanation of the steps that were taken... includ[ing] the raw field names that were used, the calculations that were done, the filters that were applied, the sort order". It also reports how long the agent "thought". When Advanced analytics is on, a **Code** tab shows the generated Python. Older Looker Studio docs called this "Show reasoning". — [Google Cloud: Converse with Looker data](https://docs.cloud.google.com/looker/docs/conversational-analytics-looker-data); [Looker Studio CA doc](https://cloud.google.com/looker/docs/studio/conversational-analytics-looker)
- **Power BI Copilot verified-answer output** shows four indicators: a **"Verified checkmark"** (human-reviewed and approved), a **"Matched trigger phrase"** (the exact or semantically similar phrase it matched, which "helps users understand how their prompt was interpreted"), a **"Textual answer"** (an AI summary) and **"How Copilot arrived at this"** (underlying data and logic, including applied filters). The doc notes a usability gap: the "matched on" phrase does not update to show filters taken from the prompt, even though the data does. Doc updated 2026-09-10. Verified answers are still in preview, and the doc warns not to rely on RLS behaviour "during preview". — [Microsoft Learn: Verified answers](https://learn.microsoft.com/power-bi/create-reports/copilot-prepare-data-ai-verified-answers)
- **ThoughtSpot Spotter** shows its interpretation through the answer title and the **search tokens** used to build the answer, and follow-up questions highlight which tokens changed. Clicking a token opens a review window. An Edit button opens an "Edit Answer" window where tokens, measures and attributes can be changed. — [ThoughtSpot: Getting started with Spotter (10.10)](https://docs.thoughtspot.com/cloud/10.10.0.cl/spotter-getting-started) (search-result summary; the 10.15 page returned 404 when fetched)
- **Cube D3.** The AI Data Analyst returns results in chat as "Semantic SQL Tool Call Messages". The user can open the query in Data Explorer, edit it, run it, and "send the updated query back to the chat" as feedback. — [Cube blog: Unleashing agentic analytics with Cube D3](https://cube.dev/blog/unleashing-agentic-analytics-with-cube-d3) (vendor)
- **Tableau Pulse with Tableau Agent** answers free-text questions "with key insights, visualizations, source references, and suggested follow-up questions". The basic "Ask" button matches the question to insights that already exist. — [Tableau: Explore Metrics with Tableau Pulse](https://docs.salesforce.com/tableau/current/en-us/online/pulse_explore_metrics.md)

### Inferences
- A React rebuild could use this stack: (1) an answer card with a one-sentence answer and a chart; (2) a "Read as" chip row of editable interpretation tokens (metric, filters, time, grain), as in Spotter tokens and Genie "Applied filters"; (3) a collapsible "How I got this" panel with a numbered plain-English step list (Looker Text, Genie Thinking steps); (4) a "Show code" disclosure; (5) a trust line ("Verified" or "Matched saved answer: <phrase>"); (6) a feedback row with Correct, Fix it and Ask an expert.
- Step lists win over DAGs for answer provenance. None of the answer tools above shows a lineage graph inside the answer. Graphs appear only in catalog tools (see section 4).

### Gaps
- I found no exact screenshots or pixel layouts, only documented labels. The ThoughtSpot "latest" coaching pages returned 404, so the newest Spotter Agent flow is unverified.

## 2. Trust badges and verified/trusted answers

### Takeaway
Trust is shown by a small checkmark or "trusted" marker that means a human-approved query or answer was reused, plus a "Show more" view naming what was reused and its parameters. Authors create these assets from a good answer ("Save as verified query", "Set up a verified answer"), and the tools now suggest new ones from usage.

### Cited Findings
- **Genie trusted assets.** A response "indicates when a user's question invokes a trusted asset". "Show more" reveals the parameter values for trusted queries, which the user can change and rerun, and the creator's comments for trusted functions. Databricks recommends trusted assets for well-established recurring questions. — [Databricks: Trusted assets](https://learn.microsoft.com/da-dk/azure/databricks/genie/trusted-assets); [Talk to Genie](https://docs.databricks.com/aws/en/genie/talk-to-genie). I could not confirm the exact badge text.
- **Genie benchmarks.** Authors add questions, optionally with reference SQL. Runs grade each answer Good or Bad by comparing results, and questions without reference SQL need manual review. Runs are listed with an accuracy figure. Databricks recommends 2 to 4 phrasings per question. — [Databricks: Benchmarks](https://docs.databricks.com/aws/en/genie/benchmarks); [Databricks blog on benchmarks and Ask for Review](https://www.databricks.com/fr/blog/building-confidence-your-genie-space-benchmarks-and-ask-review). A secondhand report says Databricks claimed a 91% pass rate on a benchmark it built itself. This is vendor-run and unverified. — [Digg summary](https://digg.com/ai/il3nxnsy)
- **Snowflake Cortex Analyst Verified Query Repository (VQR).** Each entry pairs a question with SQL. When a user's question is similar to one, Analyst uses it, and the API's confidence field shows which verified query was used. In the UI, the **"Save as verified query"** button sits below an assistant answer. Verified queries can also be added in the Semantic View Editor and reused as an evaluation set. — [Snowflake: VQR](https://docs.snowflake.com/en/user-guide/views-semantic/verified-query-repository); [Cortex Analyst evaluations](https://docs.snowflake.com/user-guide/snowflake-cortex/cortex-analyst-evaluations)
- **Snowflake verified-query suggestions** appear in a right-hand panel of Snowsight (AI & ML » Cortex Analyst), up to 10 at a time. They come from frequent, non-trivial, novel queries in query history, and from common questions in Cortex Analyst, Cortex Agents or Snowflake CoWork that match no existing verified query. The author can accept, edit or dismiss each one. "Suggestions are not automatically applied." — [Snowflake: Suggestions](https://docs.snowflake.com/user-guide/views-semantic/verified-query-suggestions). Preview/GA status is not stated.
- **Power BI verified answers** are created from a visual's menu with **"Set up a verified answer"**. The author adds 5 to 7 trigger phrases (Copilot suggests some), up to 3 user-adjustable filters, and "Available to users" versus "Applied to this visual" filter sections. Limits are 250 per model and 15 trigger phrases each. Verified answers do not return when Fabric IQ is enabled. — [Microsoft Learn: Verified answers](https://learn.microsoft.com/power-bi/create-reports/copilot-prepare-data-ai-verified-answers)
- **Hex** lets teams mark endorsed tables as canonical; "the agent prefers them when several tables could answer". Hex advises building a semantic model only "where a shared, locked definition matters". — [Hex: Semantic models](https://hex.tech/product/semantic-models) (vendor). I found no doc on how Hex threads display citations.
- **Atlan certificates** have the statuses Certified/Verified, Draft, Deprecated or none. AI-created glossary assets show a distinct icon whose variant reflects the certificate status. — [Atlan: data certification](https://atlan.com/know/ai-agent/ai-agent-governance/what-is-data-certification/); [Atlan AI for glossary](https://docs.atlan.com/product/capabilities/atlan-ai/how-tos/use-atlan-ai-for-glossary-management)

### Inferences
- A good badge model has three states: Verified (human-approved asset reused), Governed (built from defined metrics but not pre-approved) and AI-inferred (the agent guessed). The third state matters most for the Minimal Ontology Principle. Most vendors show only the first state and leave the rest unmarked.

### Gaps
- I found no vendor that publicly documents a badge for "the AI guessed this term's meaning". This looks like open whitespace.

## 3. Showing "this term means X here, not the usual Y" (meaning delta) and correcting interpretations

### Takeaway
No product I found ships an explicit side-by-side of "generic meaning vs company meaning". The closest shipped patterns are these:
- ThoughtSpot coaching maps phrases to business terms, which the user accepts or rejects.
- Power BI "AI instructions" let authors write free-text business terminology.
- Atlan's glossary separates "related" terms from "recommended" (preferred) terms.
- Genie's "Fix it" and Snowflake's usage-based suggestions turn failures into candidate definitions.

The Minimal Ontology Principle explicitly calls for logging interpretations and surfacing discrepancies, but its article proposes no UI.

### Cited Findings
- **Minimal Ontology Principle** (Animesh Kumar, Modern Data 101, 9 June 2026): "Define only the delta". Effort belongs "deciding where your enterprise's meaning diverges from the one the model already has". In mature loops "Agent queries and their semantic interpretations are logged", discrepancies are "surfaced to data platform teams as definition candidates", and the layer "grows not from top-down ontology engineering workshops". The model's confusion "is not a bug, but a methodology".
  - Example terms: "revenue" (SaaS recognised MRR vs marketplace take-rate on GMV vs services billed hours); "net revenue = billed revenue minus refunds and credits, recognised on cash receipt, excluding intercompany"; "active user = at least one transaction in last 28 days, excluding internal test accounts"; "customer" as a commonly misread term.
  - The article recommends writing description fields for the model and using context injection rather than fine-tuning. It proposes no UI.
  — [Modern Data 101: Minimal Ontology Principle](https://moderndata101.substack.com/p/minimal-ontology-principle)
- **ThoughtSpot Spotter coaching.** "+ Add to Coaching" saves a question as a reference question, and the user can accept or reject the business terms mapped to tokens. Coaching is global by default for users with edit rights. ThoughtSpot advises coaching "when the correct interpretation isn't obvious from the data model". Thumbs-down feedback goes to admins in a "Spotter Conversations" Liveboard, and the FAQ says Spotter learns from edits made after a wrong interpretation. — [ThoughtSpot: Coach Spotter](https://docs.thoughtspot.com/cloud/10.10.0.cl/spotter-coach); [What to coach and what not to coach](https://docs.thoughtspot.com/cloud/10.13.0.cl/spotter-coach-not-coach); [Spotter FAQ](https://docs.thoughtspot.com/cloud/latest/spotter-faq) (via search summaries; I could not fetch the latest pages)
- **Power BI AI instructions** are free text "about the semantic model that help Copilot understand your business, terminology, and how to prioritize the data". Microsoft advises starting with the 5 to 10 most common questions and expanding from user feedback. — [Microsoft Learn: Prep data for AI](https://learn.microsoft.com/power-bi/create-reports/copilot-prepare-data-ai); [AI instructions](https://learn.microsoft.com/power-bi/create-reports/copilot-prepare-data-ai-instructions)
- **Atlan glossary term page.** It shows the name, alias, parent glossary and categories, a README (expanded definition, purpose, business context, supporting material, certificate) and the owner. "Related terms" act as "see also", while "Recommended terms" give the preferred form of usage. Atlan AI generates an overview for every term. — [Atlan: What is a glossary](https://docs.atlan.com/product/capabilities/governance/glossary/concepts/what-is-a-glossary.md); [Atlan README template](https://atlan.com/resources/readme-business-glossary/); [Atlan glossary term page demo](https://atlan.com/demos/glossary-term-page.md) (vendor; the demo transcript is partly garbled)
- **Hex** guidance tells the agent: "Don't guess or swap in a look-alike metric. Say it isn't covered, and point to the closest endorsed table." This is an "out of definition" response pattern. — [Hex: Semantic models](https://hex.tech/product/semantic-models)
- **Snowflake suggestions** surface unmatched common questions as candidate verified queries. This is the closest shipped version of "grow the layer from failures". — [Snowflake: Suggestions](https://docs.snowflake.com/user-guide/views-semantic/verified-query-suggestions)
- **Genie** "Fix it" collects structured error reasons, and "Request review" routes a flagged answer to the space author. — [Databricks: Talk to Genie](https://docs.databricks.com/aws/en/genie/talk-to-genie)

### Inferences (design proposals, not shipped features)
- **Meaning-delta card** for a term page: two columns, "What an AI assumes" (the generic or LLM-default meaning, auto-generated) and "What it means here" (the company definition, owner, certified badge). A highlighted "Difference" line sits between them, for example: "Here: cash-received, net of refunds, excludes intercompany". A term with no meaningful difference would show "Uses the standard meaning, no definition needed", which applies the Minimal Ontology Principle visually.
- **"I read this as" strip** shown before or with the answer: chips for metric, filters, time and grain, each marked with where its meaning came from, using Company definition, Verified answer or AI guess. AI-guess chips get a dashed outline and a "Correct this" action. A correction offers "Save as company meaning?", which creates a draft definition. This combines Spotter tokens and coaching with Genie Applied filters.
- **Discrepancy inbox** for data owners: grouped log rows of "agent read X, user meant Y", with counts and "Make definition / Dismiss", in the style of Snowflake's suggestion panel (up to 10, never auto-applied) and ThoughtSpot's Conversations Liveboard.
- **Coverage meter:** "N terms defined; M misreads this week; K terms use the standard meaning". This shows the ontology growing from failures rather than from workshops.

### Gaps
- I found no shipped "generic vs company definition" side-by-side in any vendor product. I found no public detail on "did you mean" disambiguation UIs beyond Genie's clarifying question, which has no documented label. AtScale and Collibra were not researched in depth because of tool-call limits.

## 4. Metric/definition pages and lineage/provenance shown simply

### Takeaway
Metric pages in catalogs pair a definition with a lineage DAG, usually behind a tab or button. Answer tools prefer flat lists (filters, fields, steps, source references). Tableau Pulse explains "why it changed" with ranked drivers and detractors drawn only from the dimensions an analyst curated, not with lineage.

### Cited Findings
- **dbt Catalog** (formerly Explorer) offers an interactive DAG of the project. The full lineage graph sits behind the Overview page's "Explore Lineage" button. The Semantic Layer also records "how a metric is calculated and who defined it". — [dbt: Discover data with Catalog](https://docs.getdbt.com/docs/explore/explore-projects); [dbt Semantic Layer](https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl.md)
- **DataHub metric page** (comparable tool) has an expression section, tags such as Certified, and a lineage tab tracing Metric → Semantic Model → Logical Dataset → Physical Dataset. — [DataHub: Metrics and semantic models](https://docs.datahub.com/docs/features/feature-guides/metrics-and-semantic-models)
- **Tableau Pulse "Insights Exploration" page.** The header shows the current value, the % change vs the prior period, the definition's filters and insights. An Overview tab holds a line chart, and a Breakdown tab shows contributions by dimension. Suggested questions appear per insight. — [Tableau: Explore metrics](https://docs.salesforce.com/tableau/current/en-us/online/pulse_explore_metrics.md)
- **Tableau Pulse insight types** include Top Drivers (same direction as the metric change), Top Detractors (opposite direction), Concentrated Contribution and Correlated Metrics (Tableau+ only). The analysis is restricted "to the measures and dimensions referenced by the metric definition, as curated by analysts". Insight types are toggled in the Insights tab of the metric definition settings. — [Tableau: Insight types](https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm)
- **Snowflake semantic views** are created and edited in a Snowsight Semantic View Editor. — [Snowflake: Semantic View Editor](https://docs.snowflake.com/user-guide/views-semantic/editor)

### Inferences
- For business users: inside an answer, show a "Sources" chip row (metric definition, table, verified query) and a 3 to 6 step list. Keep a mini lineage graph only on the metric page, behind a "See where it comes from" button, as dbt does with "Explore Lineage". A Pulse-style "why it changed" panel works best limited to the dimensions the definition names, which is the same discipline as "define only the delta".

### Gaps

I did not fetch Cube Playground, Looker LookML field-description tooltips, Gemini-in-Looker explanation text or AtScale UI details, so those are uncovered. G2/Reddit usability reviews were not gathered.
