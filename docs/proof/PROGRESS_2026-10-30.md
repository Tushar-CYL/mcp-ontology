For the manager and Arin. This is the status after the research pack
(`docs/research/`), the plan (`docs/strategy/`), and the first build pass.
Everything below is measured on this machine; the numbers live in
`docs/benchmark/` and the tests in `tests/`.

## What landed

| Area | What now works | Evidence |
|---|---|---|
| Any source, robustly | A bad file is skipped with a reason; the rest of the folder is read; duplicate stems become distinct tables; a zero-byte file is ignored; CSV is retried tolerantly | `tests/integration/test_sources_robust.py` |
| Warm reopen | Every source table is materialised, so a second process opens the graph and answers without rebuilding or re-attaching (this was a crash before) | `TestWarmReopen`, `docs/benchmark/baseline/*_after_core.md` |
| Multi-source | Several sources in one graph; `source_id` on every class/node/edge; per-source counts and rebuild; ambiguous queries refuse to guess | `test_multi_source.py` |
| Cross-source identity | `resolve()` proposes `same_as` candidates with confidence and an explanation; nodes are never merged silently; approval changes only the link | `knowledge_graph/resolve.py`, `test_resolve.py`; smoke: 3 product masters → 50 candidates at 0.70 |
| Human review gate | Propose → approve/reject → audit; `publish` refuses while items are pending; CLI `python -m review.cli` | `review/store.py`, `test_review.py` |
| Agent Context Builder | Entity + properties + direct/indirect links + cross-source matches + findings + review state, packed under a hard budget, citation on every fact, dropped list reported | `context/assemble.py`, `test_context_builder.py` |
| API + MCP | One service exposed by a local HTTP API and an MCP stdio server; no new dependency | `api/`, `test_api.py`, `docs/API.md` |
| UI | The Context tab now shows the real pack: kept/dropped counts, review-pending, and what was left out | `app.py` |

## What the demo can show now

1. **Authoring:** `python run.py data\fixtures\lake100` — 100 tables, 100
   classes, 141 relations, 0 dangling, in seconds; a deliberately bad file in a
   folder is reported, not fatal.
2. **Multi-source:** two source paths in one graph; per-source counts; a query
   names its source or refuses.
3. **Cross-source insight:** build ERP/PIM/marketplace product masters as three
   sources; `resolve()` returns candidates with confidence; the context pack
   says "Same Product p1 appears in pim (confidence 70%, proposed)".
4. **Trust:** open the review CLI, approve a metric, and watch `publish` move
   from refused to approved; every decision is audited.
5. **Consumption:** `python -m api.http` and `python -m api.mcp_server`; an
   agent asks `context.build` and gets cited facts + dropped list + review state.

## What is still missing (honest)

- **Review screen in the UI** — the CLI/API gate exists; the Streamlit queue is
  the next screen (the four-tab test pins the current UI, so this is a
  deliberate next change, not a silent omission).

  modelled as `attribute_rules` but not enforced yet; today the answer shows
  the alternatives and confidence instead of choosing silently.
- **Golden-question score** (5/5 via API/MCP) — not yet measured; this is the
  first acceptance run for the next pass.
- **Search over documents**, cloud connectors (Snowflake/Databricks),
